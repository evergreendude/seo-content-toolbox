How the Content Analyzer works

Paste a draft and it scores how well the writing is built for search engines and for AI/RAG pipelines. It has two separate actions:

Analyze — the structured pass. Rates keyword coverage against your primary/related keywords, checks readability, and breaks the text into chunks the way an embedding/RAG system would ingest it, so you can spot thin or off-topic sections. This is the objective, metric-driven report.

Editorial Review — a different pass. Claude acts as an exacting editor and gives direct, candid, constructive feedback (under 200 words) on whether the writing actually lands — what to cut, tighten, or rethink. Use it for a qualitative gut-check on voice and clarity, not for scores.

Options: Target audience tunes both passes to who you're writing for. Chunking strategy controls how the text is split — Document (by headings), Fixed size (uniform word counts, best for embeddings), Semantic (by topic shift), or Paragraph — mirroring real RAG ingestion strategies.

Uses your own Anthropic API key (entered once, stored only in this browser).

How the SEO Audit works

Give it a URL and it runs a heuristic technical-SEO audit — indexability, metadata & head tags, content & headings, structured data, performance signals, mobile/UX, and internationalization — returning findings ranked by severity, each with a "why it matters" and a concrete fix.

Heuristic, not a crawler: it reasons about the page against known best practices rather than running a live Lighthouse crawl. That makes it fast and explanatory — great for triage and for teaching a client what's wrong — but pair it with a real crawl for exhaustive coverage.

Options: Audit scope toggles which areas to check. Output depth (full / priorities / executive) and Audience (SEO / developer / client) reframe the same findings — e.g. a developer gets the exact tag to add; a client gets the plain-English ranking impact.

How Keyword Clustering works

Paste a keyword list and it groups them by real Google ranking overlap: for each keyword it pulls the top ~10 results, then merges keywords whose SERPs share enough of the same URLs — because that means one page can rank for all of them. It answers "how many pages do I actually write, and what does each target," with evidence instead of guesswork.

Why this beats grouping by words: "how to grow tomatoes" and "growing tomatoes in containers" sound identical but rank different pages (two pages); keywords with totally different wording can share 7/10 URLs (one page). Only the live SERP reveals this.

Options: Merge threshold = how many shared URLs to cluster on — 2 = broad groups, 3 = Ahrefs-standard, 5+ = tight. Enrich adds search volume, difficulty, and intent per keyword. Each cluster gets a primary keyword, the shared "pages to beat," and a one-click SEO brief.
