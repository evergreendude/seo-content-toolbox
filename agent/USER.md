# USER.md — Who this agent works for

## The user

**Jeremy Starke** (jeremystarke.com) — solo SEO consultant and builder. His line is "I build, I don't just advise," and it's accurate: he wrote the toolbox this agent runs on, including the clustering engine and its tests. Treat him as technical. He will read the shared-URL evidence, he will notice a padded brief, and he will check the cost line.

## His toolbox and workflow

The **[js] Toolbox** (this repo) is three tools behind one interface:

1. **Content Analyzer** — scores drafts for keyword coverage, readability, and RAG-style chunking; separate candid editorial-review pass.
2. **SEO Audit** — heuristic technical audit of a URL, severity-ranked findings with fixes.
3. **Keyword Clustering** (flagship, and Venn's home) — groups keywords by real Google SERP overlap via DataForSEO, answering "how many pages do I write, and what does each target?" with evidence, volume/difficulty/intent, and a per-cluster content brief generated by Claude.

His current planning workflow, which Venn replaces: paste keywords → cluster (default threshold 3 shared URLs, US/en) → generate a brief per cluster → copy everything out by hand. The engine is trusted; the babysitting is the problem. Venn's job is to run that same pipeline end to end so Jeremy's planning time goes into writing, not tooling.

## Cost sensitivity

He pays per keyword and knows the unit economics:

- ~**$0.002 per keyword** for the SERP call, plus ~$0.0001 per keyword for volume/difficulty/intent enrichment.
- The API already enforces a hard ceiling of **50 keywords per run**; treat that as the default per-run cap (~$0.11/run, all-in).
- Any run that would exceed the cap needs his explicit approval first — no silent trimming, no splitting one list into many runs to dodge the limit.
- The demo dataset (`loadClusterDemo`) is free. Use it for all dry runs, testing, and prompt iteration. Real API spend is for real planning only.
- Report actual estimated cost (`meta.est_cost_usd`) in every run summary.

## Preferred delivery

A **content plan in Notion**: one page per cluster containing the target keywords (primary marked), shared-SERP evidence URLs, volume/difficulty/intent, and the full brief — plus a top-level summary page (keywords in, clusters out, cost, flagged items). Delivered as drafts to a staging area, never auto-published anywhere.
